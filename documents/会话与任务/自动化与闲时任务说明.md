# 自动化与闲时任务说明

> 范围：automation（cron 定时任务）、桌面 scheduler 进程派发、off-peak 闲时任务。代码基准：main@a4b44451（v4.0.0）；核对日期：2026-11-25。

## 自动化（automation）

代码：`packages/services/src/session/` 下 `automationCron.ts`、`automationRepo.ts`、`automationService.ts`、`automationCronValidation.ts`、`automationIntervalCarrier.ts`（定时用 croner）。

- 任务定义持久化在 tasks-index SQLite 的 `automations` / `automation_runs` 表（`automationRepo.ts`）。
- 调度规则校验已从 `automationService.ts` 抽出到 `automationCronValidation.ts`（`isValidCronExpr`、`assertValidAutomationScheduleRule`、`InvalidAutomationScheduleRuleError`）；`automationCron.ts` 再导出 `isValidCronExpr`，`automationService.ts` 只导入 `assertValidAutomationScheduleRule` 并再导出该错误类型。
- **项目化执行域**：automation 行可带 `project_id` / `host_id` / `additional_directories`（`automationRepo.ts:85-87`，迁移 `0004_project_execution_scopes`）；创建时经 `prepareProjectExecution(projectId)` 解析成执行快照再落库（`automationService.ts:163-167`），绑定项目后不允许再绑 `targetTaskId`（`project.bound-task`）。
- 自暂停 API：`AutomationService.pause(automationId, scope?)`（`automationService.ts:385`）——执行轮自暂停（CronPauseSelf），只暂停当前 workspace 内 active 的任务并返回是否生效。
- UI 侧管理：`packages/ui/src/store/automationManagementStore.ts`。

## 桌面 scheduler 进程（packages/desktop/src/scheduler/）

常驻 cron scheduler UtilityProcess：轮询 tasks-index 的 automations / off-peak 任务并**派发回 main**（`src/scheduler/index.ts` 头注释）。链路：

```
scheduler utilityProcess（轮询 tasks-index）
  → 派发到 Main（src/main/desktopCronScheduler.ts fork）
  → Main 转发到对应窗口 Host
  → Host 内 cron/off-peak 派发（src/host/index.ts）执行任务
```

架构约束：Main 只做进程调度和消息转发，不承载任务业务状态（根 `AGENTS.md`）；任务事实的唯一所有者是 tasks-index + Host 内 local services。

## 闲时任务（off-peak）

代码：`packages/services/src/session/` 下 `offPeakTaskService.ts` / `offPeakTaskRepo.ts`（表 `off_peak_tasks`）、`offPeakServerClient.ts`、`offPeakRuntimeModel.ts`、`offPeakMockGateway.ts`、`offPeakResidentExecutions.ts`、`offPeakWorkspaceIdentityMigration.ts`。

- 语义：低峰排队执行的任务；与 automation 的差别在于触发方式（闲时窗口 vs cron 表达式）。
- `offPeakServerClient.ts` 对接服务端闲时调度；`offPeakMockGateway.ts` 提供开发态 mock。
- 同样支持项目化执行域：`off_peak_tasks` 行带 `project_id` / `host_id` / `additional_directories`（`offPeakTaskRepo.ts:54-56`，迁移 `0004_project_execution_scopes`）。
- `offPeakWorkspaceIdentityMigration.ts` — workspace 身份迁移时，在调用方的写事务内取消源 key 下与目标 key 冲突的闲时绑定，避免撞部分唯一索引导致整个迁移回滚。
- UI 侧：`packages/ui/src/store/offPeakTaskStore.ts`。
- 设计语言中 idle-time 有专用配色 token（`--color-idle-task` / `--color-idle-task-surface`，见根 `DESIGN.md`），用于闲时队列/暂停标签，区别于定时任务的绿色处理——改 UI 时不要混用。

### 驻留执行与票据生命周期（v4.0.0）

`offPeakTaskService.ts` 头部注释（`:3-10`）改写了 v4.0.0 的收口语义：

- **expired 且 queued → 失败收口**：轮询 `/ticket/status` 返回 `expired` 且任务处于 `queued` 时直接 `markTerminal(failed, failureReason=OFF_PEAK_TICKET_EXPIRED_MARKER)`（`offPeakTaskService.ts:756-762` → `:517-553`）；**只有手动 Continue 允许补号**，同步周期不得自动重取号（`:555-556`）。手动 Continue 的语义是：票还活着 = 恢复派发（零成本）；票已废（expired / not_found / 无票）= 此刻手动重取号回队尾（额度消耗必须由用户显式动作触发，`:375-379`）。
- **3102 到期：驻留 CLI 请求换票时失败收口并停止执行，不自动消耗新额度**（`:524-549`）——3102 混用了过号与运行时长耗尽，自动补号会静默消耗下一次额度，因此统一失败后由用户重试；收口时先落终态，CLI 停止后的迟到结果不能覆盖失败，已接管的用户执行也不能被旧过期事件停止。

驻留执行（resident execution）由 `offPeakResidentExecutions.ts`（`OffPeakResidentExecutions`）维护：**Host 只关联驻留执行和票据请求，后台工作清单与完成判断仍由 CLI 唯一维护**（`:35`）。生命周期事件与控制参数 schema 在 `packages/shared/src/off-peak-execution.ts`：

- **注册**：`register()` 按 `offPeakTaskId` 登记 `executionId` / `sessionId` / `ticketId`；同一任务重复注册未终态执行会抛 `off_peak_execution_already_registered`（`:47-74`）。
- **续期（renew）**：CLI 发 `ticket_needed` 事件时按 `renewalId` 推进，`retakeGuard` 保证旧交接不被迟到 ACK 倒写；续票入口在 Host 侧就是失败收口（`offPeakTaskService.ts:140-141` 把 `renew` 接到 `handleTicketExpiredDuringRun`）。
- **替换（replace）**：新票经 `deliverTicket()` 下发 `replace_ticket` 控制命令让 CLI 安装（`:151-187`）；RPC 抛错不代表 CLI 未安装，原票与凭据保留，只有明确拒绝才重新申请（`:207-224`）。
- **接管（takeover）**：`user_takeover` 事件把执行标记为用户所有（`userOwned`），此后 Host 不再自动续票或回队重取（`:116-119`）。
- **释放（release）**：`ticket_released` 事件释放票据；释放不改变任务终态，失败随轮询周期捎带补报（`offPeakTaskService.ts:155-156`）。
