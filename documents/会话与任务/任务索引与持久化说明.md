# 任务索引与持久化说明

> 范围：packages/services 的任务索引（SQLite）、设置持久化、数据目录规则、Claude 会话导入。代码基准：main@a4b44451（v4.0.0）；核对日期：2026-11-25。

## 任务索引（SQLite）

- 存储：Node 内置 `node:sqlite`；库文件 `~/.zcode/v2/tasks-index.sqlite`（`packages/services/src/paths.ts:215-217`）。`tasksDatabase/startup.ts` 已删除；createRequire 改为分散在各自仓库文件里就地加载 `node:sqlite`（避免打包器改写内置模块引用）：`taskIndexRepo.ts:34`、`automationRepo.ts:34`、`offPeakTaskRepo.ts:27`、`controllerRemoteIdentityMigration.ts:7`、`sourceServerWorkspaceAliasRepo.ts:22`。
- Schema 与迁移（`packages/services/src/session/tasksDatabase/`）：
  - `schema-v1.ts` — 初始 schema；
  - `migrations.ts` — 迁移使用**冻结 checksum**：已发布迁移的 SQL 不得改动，只能新增迁移；`runTasksDatabaseMigrations(db, scopeOrOptions)` 已由同步改为 **async**，第二参可为 scope 字符串或选项对象，`scope` 取值 `"base" | "controller-remote" | "source-server"`；
  - `prepared.ts` — prepared statements；
  - `official-glm-selection-v3.ts`、`provider-selection-v2.ts` — 任务上的模型选型记录迁移；
  - `controller-remote-schema-v4.ts` — 控制端远端身份审计表；
  - `source-server-schema-v5.ts` — source-server 的 workspace 别名表与迁移账本接管规则。
- 迁移执行器统一到共享框架 `packages/shared/src/sqlite-migrations/`（对外入口 `@zcode/shared/sqlite-migrations`，含 `runner.ts` / `backup.ts` / `restore.ts` / `legacy.ts`）；tasks 账本表名为 `tasks_schema_migration`，迁移账本同时负责把备份写到 `{dataRoot}/backup`（`migrations.ts:225`，`dataRoot` 取库文件所在 `v2` 目录的上一级，即 `~/.zcode/backup`）。
- 迁移 id：`0001_adopt_task_schema`、`0002_provider_selection`、`0003_official_glm_selection`、`0004_project_execution_scopes`、`0006_task_group_admissions`、`0007_task_permanent_deletion`；按 scope 追加 `0004_controller_remote_identity`（controller-remote）与 `0005_source_server_workspace_schema`（source-server）。
- 新增表：`task_purge`（永久删除账本 + 归档/插入守卫触发器）、`task_group_admissions`、`controller_remote_identity_migrations`、`workspace_alias`、`workspace_migration_schema_version`、`workspace_migration_ledger` / `workspace_migration_conflicts`（及其 `_v2` 过渡表）。
- 仓库层按域拆分：
  - `taskIndexRepo.ts` — `tasks` 主表（只读 join `off_peak_tasks`）；
  - `automationRepo.ts` — `automations` / `automation_runs`；
  - `offPeakTaskRepo.ts` — `off_peak_tasks`；
  - `packages/services/src/task-groups/`（`contract.ts`、`repository.ts`、`migration-v6.ts`）— 任务分组域（`task_groups` / `task_group_members` / `task_group_view_node_orders` / `task_group_admissions`）；
  - `packages/services/src/project-storage/` — 项目存储域（Host 侧 project repository 与版本化迁移）。
- 搜索文本：写入路径不再对正文做索引上限截断——原 `TASK_SEARCH_TEXT_MAX_CHARS = 200_000` 常量已从仓库层删除，只剩 `TASK_SEARCH_SNIPPET_MAX_CHARS = 140` 的**展示摘要**上限（`taskIndexRepo.ts:110`、`:234`），用于命中片段摘要展示，不是索引膨胀控制；正文侧的 200_000 上限只存在于生产端 `packages/services/src/zcode-agent/zcodeTaskIndexSyncer.ts:1947`。
- 分组视图类型已从 `zcodeTaskListTypes.ts` 迁出（该文件现在只剩列表查询/结果类型）：分组领域契约（`TaskGroup` / `GroupTaskRef` / `GroupNode` / `TaskGroupStructure` / `ITaskGroupService`）落在 `packages/services/src/task-groups/contract.ts`；投影类型（`ZCodeGroupedTaskView`、`ZCodeTaskGroup` 等）落在 `packages/ui/src/project-sidebar/grouped/types.ts`。
- 服务层 `zcodeTaskService.ts`（IZCodeTaskService）：v4 会话与任务的对外服务契约，v4.0.0 明显扩张。除 task 列表、置顶、归档外，新增 `checkCodexConnectivity()`（`:204`）、`switchAgent()`（`:578`）；Bot 话题与群任务输入（`readBotTopicSummaries` / `invalidateBotTopicInputs` / `readBotTopicExecution` / `stopBotTopicExecution`，`:238-263`；`getBotGroupTaskBlockReason` / `cancelBotGroupInput` / `submitBotGroupInput`，`:266-294`）；v4 会话删除预览（`V4SessionDeletionPreview`，`previewArchivedTaskDeletion` / `previewArchivedTaskDeletions`，`:689-697`）；`createTask` 新增 `projectId` / `additionalDirectories` / `permissionScope`（`:209-235`）。

## 数据目录规则（packages/services/src/paths.ts）

`getDataBaseDir()` 优先级：`setDataBaseDir()`（运行时注入）> 环境变量 `ZCODE_DATA_BASE_DIR` > `homedir()`；数据写入其下 `.zcode/`。对 Windows 安装目录做禁止校验（不允许把数据目录设在 Program Files 类位置）。

## 设置持久化

- `setting.json`：`packages/services/src/setting/settingService.ts`（路径拼接见 :255 `join(resolveUserHomeDir(), ".zcode", "v2", "setting.json")`；`getSettingsDir` 在 :269 定义为 `dirname(settingsFile)`），坏 JSON 容错读取 + `settingsWriteQueue.ts` 写队列。
- 原子写：`packages/services/src/fs/atomicFileUtils.ts`（先写临时文件再 rename 的原子文件写工具，全仓库通用）。

## Claude 会话导入

`packages/services/src/session/claude-native/`：

- 解析 Claude 原生 JSONL 会话格式（`claudeNativeSessionImportParser.ts`）；
- 导入**只能由 CLI 创建持久会话**：`createImportedSession` 由可选变必填（`claudeNativeSessionImportService.ts:47`、`:125`，代码注释：导入只能由 CLI 创建持久会话，备份文件不能成为第二个会话事实写者）；
- 导入落库改走 `taskIndexRepo.updateTaskPresentation` + `updateTaskState`（`claudeNativeSessionImportService.ts:136`、`:142`），不再由 import service 直接把会话转成 ZCode 任务索引记录；`persistImportedClaudeTask` 的写入函数不再被 import service 调用，只保留 legacy 快照落盘与搜索正文构造；
- 解析器新增「Unknown command」「Args from unknown skill」诊断（正则 `:386-387`，`parseClaudeNativeUnknownCommandWarnings` `:515`）与可见轮次匹配（`selectClaudeNativeUnknownCommandWarningAfter` `:557`），把 Claude Code 未知 slash command 拆成的两条 system warning 合成可展示的失败原因；
- 历史修复逻辑仍在 `importedClaudeHistoryRepair.ts`（`repairImportedClaudeSessionSnapshot`），由 `zcode-session/importedClaudeSessionRepair.ts` 在读/续会话时回填异常历史。

配套测试：`packages/services/test/` 现只剩 `fixtures/`、`helpers/` 与两个新测试（`inputPredictionSwitch.test.ts`、`webRemoteProjectTreeActivity.test.ts`）；原 `importedClaudeRecovery.test.ts` 与 `nonCliAcpRetirement.test.ts` 均已删除。

## 风险与注意

- 迁移 checksum 冻结：改 `migrations.ts` 里既有迁移会触发校验失败（`isMigrationApplied` 抛 `checksum_mismatch`），只能追加新迁移。迁移执行器已统一到 `@zcode/shared/sqlite-migrations`，迁移账本同时负责备份到 `{dataRoot}/backup`。
- session 模块在 `architecture-policy.yaml` 中仍是 legacy（`managed: false`），其声明的公开入口 `session/contract.ts` 尚不存在。
