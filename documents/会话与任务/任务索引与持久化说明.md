# 任务索引与持久化说明

> 范围：packages/services 的任务索引（SQLite）、设置持久化、数据目录规则、Claude 会话导入。代码基准：main@29628c9（v3.14.3）；核对日期：2026-10-10。

## 任务索引（SQLite）

- 存储：Node 内置 `node:sqlite`；库文件 `~/.zcode/v2/tasks-index.sqlite`（`packages/services/src/paths.ts:185-187`）。`tasksDatabase/startup.ts` 用 createRequire 加载 `node:sqlite`，避免打包器改写内置模块引用。
- Schema 与迁移（`packages/services/src/session/tasksDatabase/`）：
  - `schema-v1.ts` — 初始 schema；
  - `migrations.ts` — 迁移使用**冻结 checksum**：已发布迁移的 SQL 不得改动，只能新增迁移；
  - `prepared.ts` — prepared statements；
  - `official-glm-selection-v3.ts`、`provider-selection-v2.ts` — 任务上的模型选型记录迁移。
- 仓库层 `taskIndexRepo.ts`：tasks / automations / off_peak_tasks 三张表；可搜索文本有截断上限（避免索引膨胀）。
- 服务层 `zcodeTaskService.ts`（IZCodeTaskService）：task 列表、置顶、归档。

## 数据目录规则（packages/services/src/paths.ts）

`getDataBaseDir()` 优先级：`setDataBaseDir()`（运行时注入）> 环境变量 `ZCODE_DATA_BASE_DIR` > `homedir()`；数据写入其下 `.zcode/`。对 Windows 安装目录做禁止校验（不允许把数据目录设在 Program Files 类位置）。

## 设置持久化

- `setting.json`：`packages/services/src/setting/settingService.ts`（路径拼接见 :60 `join(getSettingsDir(), "setting.json")`），坏 JSON 容错读取 + `settingsWriteQueue.ts` 写队列。
- 原子写：`packages/services/src/fs/atomicFileUtils.ts`（先写临时文件再 rename 的原子文件写工具，全仓库通用）。

## Claude 会话导入

`packages/services/src/session/claude-native/`：

- 解析 Claude 原生 JSONL 会话格式；
- 导入 repo/service 把会话转为 ZCode 任务索引记录；
- 历史修复逻辑（导入后修复历史会话的兼容问题）。

配套测试：`packages/services/test/importedClaudeRecovery.test.ts`（临时目录 fixture，node:test）。

## 其他会话基础设施

- `sessionMailbox.ts` — 会话邮箱（CLI 侧 hooks 也有同名 `session-mailbox.ts`，注意区分归属）。
- `sessionRealtimePort.ts` — 会话实时端口。
- `sessionTitle.ts` — 会话标题生成。
- `taskChangeSummary.ts` — 任务变更摘要。
- `legacyTaskSessionFile.ts` — 遗留任务会话文件兼容。
- `mcpWorkspaceScope.ts` — MCP 的 workspace 作用域。
- `zcode-session/`（services 根下另一目录）— agent 进程 stderr 采集、导入 Claude 会话修复（`nonCliAcpRetirement.test.ts` 覆盖退役校验）。

## 风险与注意

- 迁移 checksum 冻结：改 `migrations.ts` 里既有迁移会触发校验失败，只能追加新迁移。
- session 模块在 `architecture-policy.yaml` 中仍是 legacy（`managed: false`），其声明的公开入口 `session/contract.ts` 尚不存在。
