# 远程连接链路说明（SSH / WSL / Docker）

> 范围：从用户发起远程连接到远端 services 可用的完整链路，覆盖 desktop Host 侧实现路径，以及 server 侧远程直连入口的下线现状。代码基准：main@a4b44451（v4.0.0）；核对日期：2026-11-25。

## 入口路径（Web Server 远程直连入口已下线）

remote backend 能力（`@zcode/server/remote`）现在只有一条生产消费路径：

1. **Desktop Host 路径**：Host 进程内 `windowRemoteConnectionRegistry` 管理连接（见 [../桌面应用/进程架构说明.md](../桌面应用/进程架构说明.md)）；Host 对 remote backend 相关模块走动态 import（`packages/desktop/src/host/index.ts:158-161` 注释：ssh2 的 CJS 依赖链在 asar 打包后路径断裂，静态 import 会让 local 模式的 host process 也崩溃）。
2. **Web Server 路径：已下线**。`packages/server/src/http.ts` 原有的 `POST /api/connect-remote` 与 `GET /ws/remote/:id` **两条路由同时删除**（源码注释见 `packages/server/src/http.ts:452-453`）：旧入口会在 Server 内另起临时 stdio runtime，绕过 R3 的 Window Host → Source Server attachment 主链，**两个入口必须一起不可达**（留一条即可重新拉起临时 stdio 主链）。同时删除的还有 `remoteConnections` Map、`connectRemote`/`createRemoteBackend` 导入、`IFileService`/`IGitService`/`ISystemService`/`ITerminalService` 注册。现行为：远程连接统一走 **Window Host → Source Server attachment 主链（R3）**，Web/Lite 侧不再有独立远程入口。

## backend 抽象（packages/server/src/remote/）

- `backend.ts`：核心接口 `IRemoteBackend`（exec/upload/dispose）、`RemoteEnvironment`、`StdioStream`；新增可选钩子 `diagnoseExecFailure?()`——`exec` 命令非零退出后调用，失败来自 backend 自身传输（如 Docker daemon 不可用）时抛出带公开码的传输错误，传输正常时直接返回，由调用方按命令失败处理。
- `create-backend.ts`：`createRemoteBackend(target)` 按 `RemoteTarget.kind` 分派：
  - `ssh-backend.ts`（ssh2 连接/SFTP 上传，凭证见 `sshAuth.ts`，进度见 `sshUploadProgress.ts`）；
  - `wsl-backend.ts`（探测/UNC/流式上传；`wsl-detect.ts`、`wslProxy.ts`）；
  - `docker-backend.ts`（docker exec；`docker-detect.ts`）。
- `closeEvent.ts`：`createCloseEventController()`（对晚订阅者补发最后一次 close code，避免远端命令瞬间退出时竞态丢事件）+ `resolveRemoteExitCode(code, signal)`——把 child_process / ssh2 的 exit 参数归一为退出码：进程被信号杀死时按 shell 惯例返回 `128 + 信号值`，完全没有退出信息时返回 `255`（与 OpenSSH 收不到 exit-status 时的退出码一致）。
- 目标类型定义在 `packages/shared/src/remoteTarget.ts`。

## 连接全流程（connect.ts）

`connect.ts` 的 `connectRemote()`：

```
createRemoteBackend(target)
  → 部署（deploy.ts / deployShared.ts / zcodeAgentDeploy.ts / zcodeAgentWrapperDeploy.ts / zcodeAgentDevDeploy.ts）
  → 启动远端 agent 进程
  → performHandshake（handshake.ts：Hello/HelloAck，zod 校验，复用 @zcode/shared helloMessageSchema）
  → 建立 RemoteConnection（远端 services 代理）
```

- 远端进程 stdio 经 `stdio-socket.ts` 的 `wrapStdioStream` 包装成 `ISocket` 供 RPC（框架见 [../通信协议/RPC框架分层说明.md](../通信协议/RPC框架分层说明.md)）。
- **反向资源频道**：`ConnectOptions.topicResourceChannel`（`packages/server/src/remote/connect.ts:28`）**仅 Desktop Host 注入**，复用当前 stdio 的私有反向资源频道；连接建立后由 `connect.ts:231-235` 以 `ChannelServer` 注册 `TOPIC_RESOURCE_RELAY_CHANNEL`（`packages/shared/src/zcode-protocol/index.ts:425`）到该频道，远端 `entry-stdio` 侧在 `packages/server/src/entry-stdio.ts:94` 取同名频道对接。
- **透传环境变量**：远端 runtime 需要继承的非敏感产品环境变量按白名单过滤（`REMOTE_RUNTIME_ENV_KEYS`，`packages/server/src/remote/connect.ts:59-79`）；除既有键外增补 `ZCODE_TEST_BASE_URL`/`ZCODE_PRODUCTION_BASE_URL`、`ZAI_OAUTH_ORIGIN`/`ZAI_TEST_OAUTH_ORIGIN`/`ZAI_PRODUCTION_OAUTH_ORIGIN`、`ZAI_BUSINESS_BASE_URL`/`ZAI_TEST_BUSINESS_BASE_URL`/`ZAI_PRODUCTION_BUSINESS_BASE_URL`、`ZAI_OAUTH_CLIENT_ID`/`ZAI_TEST_OAUTH_CLIENT_ID`/`ZAI_PRODUCTION_OAUTH_CLIENT_ID`。
- 资产决策：`remoteAsset*`（缓存/CDN/预检/安装决策）、`remoteDeployLock.ts`（部署锁）、`localTarGz.ts`、`posixShell.ts`、`detectEnv.ts`。
- 开发态资产来自本地 mock-cdn / 构建产物（见 [../桌面应用/构建与打包说明.md](../桌面应用/构建与打包说明.md)），生产走 CDN + 本地缓存。
- 入口归属现状：调用 `connectRemote()` 的 Web Server 路由已下线（见上），`connectRemote()` 现在只是 `@zcode/server/remote` 的库导出（`packages/server/src/remote/index.ts:10`）；Desktop Host 的 Source Server 主链改走 `connectServerRemoteOverDuplex`（`packages/desktop/src/host/serverRemoteConnection.ts:359`）+ `serverRemoteDuplexTransport.ts`，不再由 Server 内另起临时 stdio runtime。

## Desktop Host 侧状态管理

`packages/desktop/src/host/windowRemoteConnectionRegistry.ts`：

- SSH/WSL target → 连接状态机：connecting / online / closing / failed / disconnected（**五态未变**）。
- 按 `remoteSessionId` 的会话集合；generation 管理与空闲回收。
- **Source Server 概念**：连接条目与 logical session 都带 `sourceServerId`（同一 Source 的多条 route entry 归并到一个 canonical Source entry，发布 online 前把 waiter/session 转交给 canonical owner）；`workspacePurpose` 随会话快照一起下发；连接请求可带 `membershipIntent`（`add` 新增 / `retain` 保留既有成员关系）与 `existingSourceServerId`（与既有 Source 不一致时抛 `WindowRemoteConnectionUnavailableError`）；`confirmSourceServerInstall` 用于远端安装确认门。
- **自动重连**：handle 暴露 `onDidReconnect`（同一 Source transport 自动重连完成后，services/capabilities getter 已切到新连接），registry 订阅后在换代时按新连接继续投影。
- **恢复预算**：close 事件携带 `recoverable`/`recoveryAttempt`/`recoveryLimit`/`recoveryBudgetExhausted`；`recoverable !== false` 的 close 进入 `recovering` 阶段并继续投影（不把 Renderer 停在首轮），预算耗尽或不可恢复才转 `terminal`。
- 远端 workspace 的服务集合：`remoteWorkspaceServiceCollection.ts`；附件/媒体/凭证代理：`remotePromptAttachments.ts`、`promptAttachmentTransferService.ts`、`conversationShareAttachmentService.ts`、`remoteMediaPreviewProxy(.Helpers).ts`、`remoteProviderProvisioningService.ts`。

## Host 侧 Source Server 文件族（packages/desktop/src/host/）

R3 主链在 Desktop Host 侧新增 `sourceServer*.ts` 8 个文件，另加 4 个连接/传输文件与 1 个 attachment 策略文件：

- `sourceServerConnectionManager.ts`：Source 连接状态机、重试、更新与单连接归并（共享同一代际状态）。
- `sourceServerManagementService.ts`：Source 管理快照、状态增量、更新/卸载请求的编排。
- `sourceServerDirectory.ts`：Source / Profile / Workspace 三实体的持久化、迁移与凭据重定向。
- `sourceServerReleaseResolver.ts`：Source Server release 描述符与归档解析（版本化 / 内容寻址两种资产策略）。
- `sourceServerStartupReconnect.ts`：Host 启动静默重连批次的唯一门禁编排（`remoteStartupAutoReconnectEnabled`）。
- `sourceServerRecoveryPolicy.ts`：自动恢复的终止态判定（`needs-install` / `needs-upgrade` / `identity-change-pending` / 不可重试的 `failed`）。
- `sourceServerMigrationCounts.ts`：Host 管理服务持有的迁移统计投影（远端读取不阻塞本机目录）。
- `sourceServerOperationLogs.ts`：Source 操作日志（结构化、脱敏，按 sequence 分组）。
- `connectDesktopSourceServer.ts`：Desktop 侧 Source Server 连接入口（私有回查与设置初始化随物理 Source 连接重建，每次重连重新建立）。
- `connectSourceServerTarget.ts`：Host 手动连接入口（目录持有 profile/凭据，Manager 决定实际连接归属）。
- `serverRemoteConnection.ts`：Source Server 的 HTTP+WS 连接与握手（`connectServerRemote`、`connectServerRemoteOverDuplex`）。
- `serverRemoteDuplexTransport.ts`：Duplex 字节通道适配（ssh2 / WSL / Docker 共用，屏蔽 transport 具体类型）。

另新增 `windowHostAttachmentRpcPolicy.ts`：`web-remote-replayable`（手机）只按 allowlist 暴露频道，未审阅的新注册高权限服务默认 fail-closed；`desktop-continuous` 保持完整服务面。

## 硬规则（仓库根 AGENTS.md）

- 每个窗口使用一个 window-scoped Local Host；本地 workspace 共享该 Host；远程 workspace 由窗口内的连接注册表管理，**不另建 Desktop Remote Host**。
- 手机远控连接桌面已有 Host attachment，复用会话运行时；不为手机另起 Agent、Local Host 或远程会话。
- 远程链路贯穿传递 `workspaceIdentity` 与 `remoteSessionId`，不得仅按路径匹配（详见 [双链路语义说明.md](./双链路语义说明.md)）。
