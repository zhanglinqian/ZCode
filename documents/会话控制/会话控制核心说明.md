# 会话控制核心说明

> 范围：`packages/session-control`（业务核心）与 `packages/services/src/app-control`（宿主侧实现）的分层、契约、依赖方向与测试接入现状。代码基准：main@a4b44451（v4.0.0）；核对日期：2026-11-25。

## 模块职责

`packages/session-control` 是**会话控制工具的可独立单测业务核心**：用 zod 严格 schema 定义 CLI 的 8 个、App 的 12 个会话操作（list / read / create / fork / send / wait / interrupt / rename，App 另加 listProjects / openSession / setArchived / setPinned），并在其之上做**授权判定、目标解析、输出复验与 wait 编排**。

**不含任何 IO**：不创建运行进程，不读写会话存储，不碰文件系统。全部副作用经注入的 port 出去。

| 维度 | 事实 | 来源 |
| --- | --- | --- |
| 包名 | `@zcode/session-control`（`private: true`，`type: module`） | `packages/session-control/package.json` |
| 入口 | `exports`: `./contracts` → `src/contract.ts`、`./cli` → `src/application/cli/index.ts`、`./app` → `src/application/app/index.ts`、`./testing` → `src/testing/index.ts`（**全部指向 `src` 源码**，非 dist） | 同上 |
| 内部导入别名 | `imports`: `#session-control/*` → `./src/*.ts` | 同上 |
| 唯一依赖 | `zod@4.6.5` | 同上 |
| 代码量 | 约 4271 行（src 核心约 2360 + `test/` 6 个文件约 1680 + `src/contract.test.ts` 176 + 配置） | `wc -l` 实测 |

## 分层与依赖方向

```
src/contract/     契约层：zod schema 与类型（common / cli / app / observation / results）
      ↓
src/domain/       领域层：同步纯规则，零 IO（operation-outcome / reference-scope）
      ↓
src/application/  应用层：CLI 与 App 两套互不导入的用例
      ├─ common/boundary.ts   parseInput / parseOutput / resolveTarget / authorize / assertActive
      ├─ common/wait.ts       waitForOperations（授权 → 一致快照 → 订阅有序更新 → any/all 判定 → 关闭 feed）
      ├─ cli/index.ts         createCliSessionControl（8 个方法）
      └─ app/index.ts         createAppSessionControl（12 个方法）
src/testing/      测试替身：createTestPorts / createManualDeadlines / createOperationFeed / deferred
```

**CLI 与 App 互不引用**：这是硬边界，由 oxlint 与根 lint 双重门禁强制（见下文「架构边界门禁」）。两套用例共享 `contract/` 与 `domain/`，差异通过 port 注入解决。

## 关键契约与规则

### 身份与作用域（`src/contract/common.ts`）

- 引用类型：`CliSessionRef` / `AppSessionRef` / `AppProjectRef`；作用域：`CliScope` / `AppScope`。
- **可信上下文判别联合**：`TrustedContext` = `SessionCallerContext` | `ClientCallerContext` → `AppTrustedContext`。`AppClientTrustedContext` 表示「来自客户端的调用」，授权判定路径与「来自会话的调用」不同。
- `AccessGrant` / `AccessRequest` / `AccessPort`：授权走显式 grant，不靠隐式信任。

### 输出复验（`src/domain/reference-scope.ts`）

会话控制的输出必须复验作用域，防止越权读别人的会话：

| 函数 | 作用 |
| --- | --- |
| `sessionScope` / `projectScope` | 取会话/项目的作用域 |
| `sameScope` / `sameSession` / `sameOperation` | 相等判定 |
| `scopeAllows` / `assertScope` | 作用域放行与断言 |
| `assertOutputAuthorized` | **输出授权复验** |
| `assertOutputScope` / `assertOutputSession` | 输出作用域 / 会话断言 |
| `defaultCliScope` | CLI 默认作用域 |

### wait 编排（`src/application/common/wait.ts` + `src/domain/operation-outcome.ts`）

`waitForOperations` 是本包唯一有独立状态机的部分：

1. 先授权**全部**目标，任一不通过即整体拒绝；
2. 开启**一致快照**后订阅有序更新；
3. 按 `any` / `all` 模式判定是否满足（`isWaitSatisfied`）；
4. 结束时关闭 feed（`isOperationSettled` 判定终态）。

订阅语义依赖 epoch / revision / fence / invalidated 四类标记，保证「快照之后发生的更新不丢、重连后不重复计」。**改这块要同时看 `packages/session-control/test/wait.test.ts` 与 `apps/zcode-cli/packages/bootstrap/tests/session-control/` 的进程级用例。**

## 架构边界门禁

session-control 是全仓**唯一有专属 lint 覆盖块**的包：

| 门禁 | 实现 | 约束 |
| --- | --- | --- |
| oxlint 覆盖 | `.oxlintrc.json` overrides，`files: ["packages/session-control/src/**/*.ts"]` | `no-restricted-imports`：禁 `node:*`/`electron`/`react`/`zustand`/`@zcode/services`/`@zcode/shared`/`@zcode/core`/`@zcode/bootstrap`/`**/services/src/**`/`**/apps/zcode-cli/**`；禁 `../cli/**` ↔ `../app/**` 互引。`no-restricted-globals`：禁 `process`/`window`/`fetch`/`setTimeout`/`setInterval`/`Date` |
| 根 lint 脚本 | `node scripts/architecture/session-control-boundary.mjs`（`pnpm lint` 的一环） | 同上边界，独立于 oxlint 复核 |
| 门禁自身的测试 | `scripts/test/session-control-boundary.test.mjs`（在 `pnpm test:architecture` 内） | — |

理由：**核心必须与环境解耦**，环境与宿主实现属于 adapters 层。

## 架构策略登记

`architecture-policy.yaml` 登记为受管模块，且是下游多个模块的前置：

```yaml
- id: session-control
  roots: [packages/session-control/src, packages/session-control/vitest.config.ts]
  managed: true
  requires: []
  publicEntrypoints: [contract.ts, application/cli/index.ts, application/app/index.ts, testing/index.ts]
  layers: {contract: contract, domain: domain, app: application}
  owner: conversation
```

下游 `requires: [session-control]` 的模块：`app-control-protocol`、`app-control`、`cli-session-control-tools`、`cli-session-control-bootstrap`、`cli-session-control-runtime`。

## 宿主侧：`packages/services/src/app-control`

`packages/services/src/app-control` 是 session-control 的**宿主侧实现层**（登记为独立受管模块 `app-control`，`owner: conversation`），负责把 ports 接到真实服务上：

| 文件 | 职责 |
| --- | --- |
| `contract.ts` / `index.ts` | app-control 的对外契约与出口 |
| `discovery.ts` / `discovery-directory.ts` | 目标发现 |
| `execution.ts` | 执行侧接线 |
| `observation.ts` | 操作观察接线 |
| `context.ts` | 上下文装配 |
| `reverseRpc.ts` | 反向 RPC（宿主 → UI 推送） |

协议类型在 `packages/shared/src/app-control/`（受管模块 `app-control-protocol`，依赖 session-control）。

`@zcode/session-control` 被 6 个包单向依赖，全部走 `@zcode/session-control/contracts` 子路径：
