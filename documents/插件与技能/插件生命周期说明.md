## 三层插件体系（先分清，避免改错地方）

仓库里有**三套**名字都带「插件」的东西，互不等价：

| 层 | 位置 | 状态 | 职责 |
| --- | --- | --- | --- |
| **旧插件管理** | `packages/services/src/plugins/`（`pluginsService.ts`、`pluginManagement.ts`、`installedPluginRoots.ts`、`officialPluginCache.ts` 等） | **已退役** | Claude Code 风格的 marketplace 增删 / install / uninstall / enable / disable。`pluginsService.ts` 中 `createRetiredOverview()` 返回空、`throwRetiredPluginManagement()` 抛错，**所有管理操作直接抛异常** |
| **扩展宿主**（新一代） | `packages/services/src/extensions/`（30 个文件：`capabilityGateway.ts`、`grantsStore.ts`、`sessionReads.ts`、`viewRelay.ts`、`auditLog.ts`、`pluginProjects.ts` …）；协议源在 `packages/shared/src/extension-host/`（33 个文件） | **现行** | 扩展协议、能力网关、授权（grants）、视图、会话读取、审计日志 |
| **对外类型 SDK** | `packages/plugin-api/`（`@zcode-dev/plugin-api` v1.4.0） | **现行，可发 npm** | 把 `shared/src/extension-host` 的协议以**纯类型**形式暴露给仓库外的插件作者 |

**改代码前先确认落在哪一层**：商店页 UI 仍归旧层（但其管理操作已退役），扩展能力实现归扩展宿主层。

## 对外插件 API（`packages/plugin-api`）

给仓库外插件作者发布的**纯类型 SDK，零运行时代码**。

| 项 | 值 |
| --- | --- |
| 包名 | `@zcode-dev/plugin-api` v1.4.0，`license: Apache-2.0`，**`private` 未设**（全仓唯一可对外发布的包） |
| 入口 | `exports`: `.` → `src/contract.ts`、`./manifest` → `src/manifest.ts`、`./sessions` → `src/sessions.ts`、`./protocol-v4` → `src/protocol-v4.ts` |
| 发布形态 | `publishConfig.exports` 四个入口全部指向 `dist/*.d.ts` 的 **types-only 条件**（发布后无 runtime condition，强制 `import type`） |
| 构建 | `tsup`（`dts.only` + rollup-plugin-dts 内联 `shared`/`session-control` 声明）；`scripts/type-only-exports.mjs` 打包后把 d.ts 导出全部改写成 `export type {...}` |
| 依赖 | 仅 `zod@4.6.5`（类型推导用） |
| 仓库内消费方 | **无**（示例插件 `jarvis` / `context-inspector` 已迁到插件市场仓库） |
| 架构登记 | `architecture-policy.yaml` `id: plugin-api`，`managed: true`，`owner: plugin`，`layers: {contract: .}` |

## 分发渠道

- **Official Marketplace**：官方运营的**主**分发渠道，市场 id `zcode-plugins-official`（`ZCODE_OFFICIAL_PLUGIN_MARKETPLACE_ID`），内容 = 内置插件 + CDN 插件。
- **Claude 官方市场**：**第二个**官方市场，id `claude-plugins-official`（`CLAUDE_OFFICIAL_PLUGIN_MARKETPLACE_ID`），GitHub git 源 `anthropics/claude-plugins-official`。它是**非强依赖**——刷新失败须被 UI 静默处理，不得阻断商店页。
- **Builtin Plugin**：随应用包分发、启动时播种进官方市场；是官方插件的子集。
- **CDN Plugin**：官方 CDN 分发、sha256 校验的 zip 包，按需下载安装。
- **Personal Source**：用户自行添加的一切来源：git/GitHub/URL/本地目录市场、inline 插件。

市场清单在 `packages/shared/src/plugin-marketplaces.ts`（`DEFAULT_PLUGIN_MARKETPLACES` 两项；`DEFAULT_ENABLED_OFFICIAL_PLUGIN_IDS` 登记默认启用的官方插件 id）。

代码位置：插件域服务在 `packages/services/src/plugins/`，官方插件缓存为 `packages/services/src/plugins/officialPluginCache.ts`（原在 `packages/shared/src/node/`，已迁至 services 侧）。**同步职责的一大半已迁到新域 `packages/services/src/data-sync/`**（`inlinePluginDataSync.ts`、`skillDataSync.ts`、`mcpDataSync.ts`、`subagentDataSync.ts`、`commandDataSync.ts`、`hookDataSync.ts`、`userConfigSyncService.ts`、`deviceSyncStateService.ts`、`contract.ts`、`node.ts`）；`packages/services/src/plugin-sync/` 保留接口层，`IPluginSyncService` 改为实现 `IDataSyncCategoryService`。安装产物与用户数据的目录规则由 `packages/services/src/paths.ts` 承担。

## 商店页结构（UI）

- **Public Segment（公开）**：仅展示官方市场目录（Featured + 分类区块）；Featured 名单由官方 CDN 目录的 `featured` 字段远程控制。
- **Personal Segment（个人）**：展示全部个人来源目录，按市场分组。
- **Installed Strip（已安装条）**：列表页顶部已安装插件图标行，点击进详情。
- **Manage Installed View（管理已安装视图）**：齿轮进入，承载插件级启停开关、更新、卸载、启用状态筛选（旧 IA 术语 Installed tab 已废弃）。

刷新语义：**Catalog Auto-Refresh**（进商店页对官方市场目录的节流后台刷新，只覆盖官方市场）与 **Manual Refresh**（顶栏刷新按钮的全市场刷新，不受节流影响）是两个动作，不要混用。

UI 状态：`packages/ui/src/store/pluginStore.ts`、`pluginManagementStore*`；服务访问：`packages/ui/src/hooks/usePlugins.ts`。

## 元数据

- **Store Listing**：目录条目的展示性元数据（显示名、icon、分类、开发者、链接、hero 图、示例提示词），不影响功能。
- **Plugin Manifest**：插件包内 `plugin.json` 的功能性定义（commands/agents/skills/hooks/mcpServers/userConfig…）。命令文件解析在 `packages/services/src/commands/commandFileParser.ts`。
- **Example Prompt**：详情页可点击提示词，点击后新建会话并预填（不自动发送），是详情页唯一的新建会话入口。

## 生命周期状态机（验收必须覆盖的点）

Plugin Lifecycle = 发现 → 查看 → 安装 → 配置 → 启停 → 使用 → 检查更新 → 升级 → 持久化恢复 → 卸载/恢复内置。每个阶段都必须同时验证**可见 UI 状态**与**对应的持久化或运行时结果**。

两个特殊状态：

- **Restorable Builtin（可恢复内置插件）**：被卸载并进入持久化抑制状态的内置插件。应用重启**不得自动重新播种**；继续出现在 Public Segment，通过「安装」入口执行干净恢复。→ 播种逻辑必须读取持久化抑制名单，这是回归测试的关键断言点。
- **Orphaned Installed Plugin（孤立已安装插件）**：对应 Personal Source 已删、但安装目录和用户数据保留的插件。仍可使用、配置、启停、卸载；来源重新添加前不能更新；重新添加同一来源后恢复目录关联。

## 硬规则

- 内置插件的「卸载」实现的是抑制 + 可恢复，不是删除——不能把 Restorable Builtin 当成未安装的 CDN 插件处理。
- 更新检查只对仍有目录关联的插件可用（孤立插件除外，见上）。
- 插件管理变更成功会发 `onMutationSucceeded` 通知（Window Host 侧信号），驱动 extension-host 重读插件清单并触发 `settings.onDidChange`；**dryRun 不触发**。
- 插件管理动作有遥测（`reportTelemetryEvent`）：install / uninstall / update / restore / configure / reset_config / enable / disable / source_* 等，含 `plugin_operation_cancelled` 取消判定。
