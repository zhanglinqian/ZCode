# 工具系统与权限说明

> 范围：Agent 工具的注册/调度/执行、bash 命令权限策略、PermissionService、hooks 信任。代码基准：main@a4b44451（v4.0.0）；核对日期：2026-11-25。所有路径相对 `apps/zcode-cli/packages/`。

## 工具系统（core/tool + contracts/tools）

- 注册与调度：`core/src/tool/registry.ts`（注册表）、`scheduler.ts`（调度）、`executor.ts` + `executor/`（执行）。
- 路径策略：`core/src/tool/path-policy.ts`（工具可访问路径边界）。
- 契约：`contracts/src/tools/` **51** 个文件定义各工具契约（bash / edit / read / write / glob / grep / webfetch / websearch / agent / skill / todo / workflow* / node-repl 等）。
- bash 只读判定：`core/src/tool/handlers/` 内 `bash-readonly-policy*` 系列 + `bash-command-permission-policy.ts`——决定哪些 bash 命令按只读处理（免审批）与哪些需要权限确认。

### 新增工具契约（contracts/src/tools/）

v4.0.0 相对 v3.14.3 新增 6 个契约文件（对应工具已在 `core/src/tool/handlers/` 落地）：

| 契约文件 | 工具 | 职责 |
| --- | --- | --- |
| `deferred-tool-call.ts` | `DeferredToolCall` | 延迟调用包装标记：原目标名与参数由调用本身保存，契约只保留还原模型协议所需的包装标记 |
| `fill-workflow-hole.ts` | `FillWorkflowHole` | 给正在等代码的动态工作流留白补上函数体；输出与 `CreateWorkflow` / `AmendWorkflow` 同形状，不新起工作流 |
| `plugin-discovery.ts` | `SearchPlugins` / `SuggestPluginInstall` | 插件发现：按关键词查市场插件候选，并给出安装/启用建议 |
| `tool-search.ts` | `ToolSearch` / `LocalToolSearch` | 工具发现入口与模式（auto/native/local/off），带 MCP 连接状态与撤销原因元数据 |
| `wait-for-mcp-servers.ts` | `WaitForMcpServers` | 等待仍在连接的 MCP server（ToolSearch 关闭时没有连接中公告时的兜底） |
| `workflow-settings.ts` | （非独立工具） | 确认窗里可调的两项 run 设置：`WorkflowAdjustableSettingsSchema` 回填事实 + `WorkflowSettingsAdjustmentSchema` 接收用户改动，CreateWorkflow / AmendWorkflow 共用 |

### core/src/tool/ 下的契约子目录

这些目录是工具入口与边界的登记处（各有 `CONTRACT.md` 说明职责与不变量），实现仍在 `core/src/tool/handlers/`：

| 目录 | 职责 |
| --- | --- |
| `cmd-readonly/` | session shell 为 `cmd` / `legacy-shell` 时的 bash 只读保守判定（白名单 `dir`/`type`/`findstr`/`where` + git 只读子命令），只供 `bash.ts` 的 `resolveBashPermissionCapability` 调用 |
| `search/` | 工具发现：登记现有搜索 schema、`ToolSearch`/`DeferredToolCall` 入口与请求投影；搜索只返回目录中的名字，不执行目标工具 |
| `session-control/` | 会话控制工具边界：`SessionControlBinding` 注入，CLI 与 App 分别注册自己的会话工具集，同名工具按可信绑定选择变体 |
| `channel-reply/` | `ReplyToChannel` 渠道回复工具入口（默认注册与 Host 发送接线当前注释停用，权限、协议与发送实现不变） |
| `topic-resource/` | `ReadTopicResource`：读取会话话题历史附件里的资源索引，是原 `ReadSessionContext(topic, attachment)` 的唯一后继 |
| `workflow-entrypoints/` | `AmendWorkflow` / `ListModels` / `FillWorkflowHole` 三个工作流工具入口的登记（均保留 deferred 分类，审批链不变） |

新增文件：`core/src/tool/deferred-call.ts`（延迟调用包装的解析与准入）、`core/src/tool/levenshtein.ts`（编辑距离，Read 的相近文件名、Edit 的行相似度与 Skill 的相近名称共用）。

## 权限（core/permission）

- `core/src/permission/service.ts` — `PermissionService`：权限决策服务。
- `core/src/permission/broker.ts` — 权限代理（跨进程的权限请求/应答）。
- `core/src/permission/rule-matching.ts` — 规则匹配。
- `core/src/permission/plan-mode-policy.ts` — Plan 模式策略。
- 运行时形态：`core/src/runtime/permission-full-access.ts`（全权限模式）、`permission-grant-recovery.ts`（授权恢复）。

## Hooks

- 运行：`core/src/hooks/runner.ts`、`configured-runner.ts`。
- workspace hooks 信任链：`core/src/hooks/workspace-hook-policy.ts` + `workspace-hook-trust-*` 系列；契约在 `contracts/src/hooks/`（`workspace-hook-trust.ts`、`workspace-hook-trust-store.ts`）；CLI 命令 `cli/src/hooks-trust-command.ts`。
- 会话邮箱：`core/src/hooks/session-mailbox.ts`（注意与 `packages/services/src/session/sessionMailbox.ts` 区分归属）。

## 设计要点

- 工具契约（contracts）与实现（core/adapters）分离：新增工具先在 `contracts/src/tools/` 定契约，再在 core 注册、adapters 提供 Node 能力。
- bash 权限是安全边界：改动 `bash-readonly-policy*` 或 `bash-command-permission-policy.ts` 必须同步核对权限规则与测试预期（已有 `core/tests/` 自动化测试覆盖，改动需跑对应用例，如 `core/tests/bash-command-permission-policy.test.ts`、`core/tests/bash-cmd-readonly-policy.test.ts`；测试体系总体见 [README.md](./README.md) 测试现状）。
- 权限模式有多个运行时形态（full-access、plan mode、grant recovery），不要在单一形态下假设行为。
- 自动化测试：`core/tests/` 已有大规模用例（v4.0.0 相对 v3.14.3，core 目录 +211629 行；`core/tests/` 下 349 个 `*.test.ts`），覆盖工具未结算调用（`core/tests/tool-unsettled-call.test.ts`）、workflow 草稿（`core/tests/workflow-draft-*.test.ts`）、workspace hook 的运行时准入（`core/tests/workspace-hook-runtime-admission.test.ts`）与 worktree 创建时序（`core/tests/worktree-creation-timeline.test.ts`）等。
