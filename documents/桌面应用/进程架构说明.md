# 桌面进程架构说明

> 范围：packages/desktop 的进程模型、spawn 链路与 MessagePort 分发。代码基准：main@29628c9（v3.14.3）；核对日期：2026-10-10。架构依据 `src/host/index.ts` 头注释与 `src/main/desktopHostProcess.ts`。

## 进程总图

```
Main (Electron 主进程, src/main/index.ts)
 ├─ fork → Window Host (utilityProcess, 每窗口一个, src/host/index.ts)
 │          ├─ local services (createLocalServices, @zcode/services)
 │          │    └─ spawn → zcode Agent 子进程 (stdio, 实现在 services 包)
 │          └─ remote connection registry (SSH/WSL, windowRemoteConnectionRegistry.ts)
 ├─ fork → cron scheduler (utilityProcess, src/scheduler/index.ts)
 └─ BrowserWindow × N (renderer 加载 @zcode/ui)

Renderer / 手机 ←MessagePort/WS→ Window Host
```

关键决策：**每个窗口一个 Host 进程**；同一窗口的 Renderer 与手机远控都 attach 到它。Main 只发一次 `InitLocal`，后续 remote connect / scoped attachment 都由同一 Host 处理（`src/host/index.ts` 头注释）。

## Main 进程

- 入口 `src/main/index.ts`（`app.whenReady()` 约 :1926，`window-all-closed` 约 :2330）。
- 窗口创建：
  - `src/main/desktopWindowLifecycle.ts` — `createWindow()`：创建主窗口、spawn 该窗口的 Local Host、注册窗口尺寸持久化、macOS 关闭行为、远程 session 的 detach/reattach 钩子。
  - `src/main/desktopWindowChrome.ts` — `createBrowserWindow()`（实际 `new BrowserWindow` 参数）。
  - 其他窗口：`src/main/aboutWindow.ts`（关于）、`src/main/index.ts:1547` 更新状态窗口；`src/main/primaryWindowCoordinator.ts` 主窗口协调；`src/main/desktopTray.ts` 托盘。
- Host 进程管理 `src/main/desktopHostProcess.ts`：
  - `spawnHostProcess()` 用 `electronUtilityProcess.fork(hostModulePath)` 每窗口拉起 Host；
  - 通过 `MessageChannelMain` 把服务端口发给 renderer（`InternalChannels.ServicePort` / `ScopedServicePort`，端口交付见 :717-730）；
  - `child.on("message")` 消费 `HostResponseTypes.*`（含 `AgentProcessSpawned/Ready/Exited/Error/Exception`），stdout/stderr 经 hostLogRelay 转日志；
  - `disposeHostProcess(AndWait)` 负责退出回收。
- 运行时环境 `src/main/desktopRuntimeEnv.ts`：`hostModulePath`、`schedulerModulePath`、`resolveBundledGlmBinaryPath()`（内置 glm/agent 二进制路径）、`buildHostProcessEnv()`、开发态 mock-cdn 目录解析（`../../mock-cdn`，:204-212）。
- scheduler 拉起：`src/main/desktopCronScheduler.ts`（fork `schedulerModulePath`）。

## Host 进程（UtilityProcess）

| 文件（相对 src/host/） | 职责 |
| --- | --- |
| `index.ts`（约 2969 行） | Host 入口：装配 local services（`createLocalServices`）、`createZCodeAgentConnectionScope`（:2003-2031）、cron/off-peak 派发、shutdown 阶段；Agent 进程生命周期经 `runtimeProcessLifecycleReporter` 回调上报给 main（:1056-1101） |
| `windowRemoteConnectionRegistry.ts` | 远程 workspace 连接注册表：SSH/WSL target → 状态机（connecting/online/closing/failed/disconnected）、按 remoteSessionId 的会话集合、generation 管理、空闲回收 |
| `windowHostAttachmentRegistry.ts` | attachment 注册表：按 attachmentId 跟踪 renderer/移动端挂载的 scoped 服务端口，支持 detach / `detachStaleRemoteSessionAttachments` |
| `windowHostControllerService.ts`（+ projection / sessionsIndexObserver） | 聚合 local + remote 各 scope 的任务/会话列表投影（IWindowControllerService） |
| `remoteWorkspaceServiceCollection.ts` | 远端 workspace 的服务集合 |
| `remotePromptAttachments.ts` / `promptAttachmentTransferService.ts` / `conversationShareAttachmentService.ts` / `remoteMediaPreviewProxy(.Helpers).ts` / `remoteProviderProvisioningService.ts` | 远端附件/媒体/凭证代理 |
| `electronPort.ts` / `hostMessagePortGuard.ts` | MessagePort 包装与入站消息守卫 |
| `hostShutdownPhases.ts` | 退出阶段 |

Main 侧对应的薄转发：`src/main/desktopRemoteSessions.ts`（`createRemoteWorkspaceSessionManager`，request/session↔端口路由）与 `src/main/desktopMainIpcRemote.ts`。

## Agent 进程归属（重要）

Main 不直接 spawn Agent。Host 内的 local services（`@zcode/services`）负责真正 stdio 拉起 Agent，实现位于 `packages/services/src/zcode-agent/zcodeAgentProcessManager.ts` 与 `zcodeAgentService.ts`；desktop 侧只消费其事件与 `IZCodeAgentService` 接口。

## Renderer 加载与连接

- 本地页面：`src/main/desktopHostProcess.ts:109-149` `loadWindow()` — 开发态（设置 `ELECTRON_RENDERER_URL`）加载 Vite dev server（端口见 `vite.config.ts`），生产 `win.loadFile(.../renderer/index.html)`（file://，query 带 restoreSession/initialWorkspacePath/launch marks）。
- Renderer 与服务连接：`src/renderer/src/main.tsx` 用 `@zcode/client` 的 `connectViaMessagePort` 消费 main postMessage 过来的 MessagePort（`InternalChannels.ServicePort`）；远程 workspace 走 `InternalChannels.ScopedServicePort`（带 attachmentId/sessionId/target），由 `src/renderer/src/remoteWorkspaceServicePortBridge.ts` 解析、`src/renderer/src/remoteWorkspaceSessionServices.ts` 构建远程 session 服务，交给 `@zcode/ui` 的 `registerRemoteWorkspaceSession`。

## 构建产物形态

`tsup.config.ts` 定义四个目标：main、preload（cjs）、host、scheduler —— `@zcode/*` workspace 包被内联（noExternal），electron/node-pty/ssh2/undici 等 external。renderer 用 Vite 8 多入口（root=src/renderer，`base: "./"` 适配 file://，`@` 别名指向 `../ui/src`）。四个 `tsconfig.*.json` 对应各目标；根 `pnpm typecheck` 对 desktop 只检查 `packages/desktop/tsconfig.host.json`。

## 风险与注意

- `src/main/index.ts`（2384 行）与 `src/host/index.ts`（2969 行）远超 400 行上限，属结构债务（见 [../代码不规范清单.md](../代码不规范清单.md)），改动时避免继续膨胀。
- 每窗口一个 Host 意味着多窗口 = 多个 Agent 进程与多份 local services；本地 workspace 共享该窗口 Host 的语义见仓库根 `AGENTS.md`。
