# 桌面进程架构说明

> 范围：packages/desktop 的进程模型、spawn 链路与 MessagePort 分发。代码基准：main@a4b44451（v4.0.0）；核对日期：2026-11-25。架构依据 `src/host/index.ts` 头注释与 `src/main/desktopHostProcess.ts`。

## 进程总图

```
Main (Electron 主进程, src/main/index.ts)
 ├─ fork → Window Host (utilityProcess, 每窗口一个, src/host/index.ts)
 │          ├─ local services (createLocalServices, @zcode/services)
 │          │    └─ spawn → zcode Agent 子进程 (stdio, 实现在 services 包)
 │          └─ remote connection registry (SSH/WSL, windowRemoteConnectionRegistry.ts)
 ├─ fork → cron scheduler (utilityProcess, src/scheduler/index.ts)
 ├─ fork → extension host (utilityProcess, 全 App 单例, src/extension-host/index.ts)
 │          └─ 由 Main 监管 (src/main/extensionHostSupervisor.ts)
 └─ BrowserWindow × N (renderer 加载 @zcode/ui)

Renderer / 手机 ←MessagePort/WS→ Window Host
```

关键决策：**每个窗口一个 Host 进程**；同一窗口的 Renderer 与手机远控都 attach 到它。Main 只发一次 `InitLocal`，后续 remote connect / scoped attachment 都由同一 Host 处理（`src/host/index.ts` 头注释）。

关键决策：**扩展进程全 App 只有一个**（`extension-host`）。它不随窗口创建/销毁，由 Main 侧监管器 `src/main/extensionHostSupervisor.ts` 拉起、监管与重启（见下文 Extension Host 章节）。

## Main 进程

- 入口 `src/main/index.ts`（`app.whenReady()` 约 2324 行，`window-all-closed` 约 2907 行）。
- 窗口创建：
  - `src/main/desktopWindowLifecycle.ts` — `createWindow()`：创建主窗口、spawn 该窗口的 Local Host、注册窗口尺寸持久化、macOS 关闭行为、远程 session 的 detach/reattach 钩子。
  - `src/main/desktopWindowChrome.ts` — `createBrowserWindow()`（实际 `new BrowserWindow` 参数）。
  - 其他窗口：`src/main/aboutWindow.ts`（关于）、`src/main/index.ts` 约 1969 行更新状态窗口；`src/main/primaryWindowCoordinator.ts` 主窗口协调；`src/main/desktopTray.ts` 托盘。
- Host 进程管理 `src/main/desktopHostProcess.ts`：
  - `spawnHostProcess()` 用 `electronUtilityProcess.fork(hostModulePath)` 每窗口拉起 Host；
  - 通过 `MessageChannelMain` 把服务端口发给 renderer（`InternalChannels.ServicePort` / `ScopedServicePort`，端口交付见约 731-742 行）；
  - `child.on("message")` 消费 `HostResponseTypes.*`（含 `AgentProcessSpawned/Ready/Exited/Error/Exception`），stdout/stderr 经 hostLogRelay 转日志；
  - `disposeHostProcess(AndWait)` 负责退出回收。
- 扩展进程监管 `src/main/extensionHostSupervisor.ts`：
  - 监管器在 `src/main/index.ts` 约 769 行创建（先于任何窗口创建），只登记窗口 Host、不直接持有扩展业务状态；
  - `trackWindowHost()` 在窗口 Host 就绪时登记（`src/main/index.ts` 约 2128 行），首个就绪的 Window Host 触发扩展进程拉起；
  - 崩溃预算：5 分钟内崩溃 3 次为上限，退避 1s / 2s / 4s；第 4 次崩溃停止重启。计划重启与重新加载不计入预算；
  - 存活探测每 5 秒一次，连续 3 次无回应判为卡死并 kill；App 退出时 `dispose()`（`src/main/index.ts` 约 1423 行）先发 dispose，1.5 秒后强杀。
- 运行时环境 `src/main/desktopRuntimeEnv.ts`：`hostModulePath`、`schedulerModulePath`、`extensionHostModulePath`（约 89 行）、`resolveBundledGlmBinaryPath()`（内置 glm/agent 二进制路径）、`buildHostProcessEnv()`、开发态 mock-cdn 目录解析（`../../mock-cdn`，约 231-240 行）。
- scheduler 拉起：`src/main/desktopCronScheduler.ts`（fork `schedulerModulePath`）。

## Extension Host 进程（UtilityProcess，全 App 单例）

由 Main 的监管器 `src/main/extensionHostSupervisor.ts` 用 `electronUtilityProcess.fork(extensionHostModulePath)` 拉起（`serviceName: "zcode-extension-host"`）。它只经 `process.parentPort` 与 Main 交换生命周期消息，业务数据走 Main 牵线的 L1 MessagePort 端口。扩展代码在运行时按插件路径动态 import，不进本 bundle。

| 文件（相对 src/extension-host/） | 职责 |
| --- | --- |
| `index.ts` | 扩展进程入口：装配 `ExtensionRegistry` / `ViewHost` / `CapabilityClient`，处理 init/probe/dispose 消息，deactivate 共用 1 秒预算 |
| `contract.ts` | 本模块的公开契约：`ExtensionHostSupervisor`、`ExtensionHostSupervisorDeps`、`ExtensionHostNetworkSettings` |
| `registry.ts` | 贡献表的唯一 owner：按扩展声明激活扩展，维护运行状态与插槽动态值，推快照/增量给 Window Host |
| `runtime.ts` | 运行时护栏：扩展未捕获错误只记日志、`process.exit` 拦截、插件归因（AsyncLocalStorage + 堆栈路径）、环境代理开关 |
| `viewHost.ts` / `viewServer.ts` | 扩展视图：视图实例经进程内 transport 连 MCP Client；写法一由宿主把 `ViewDefinition` 包成 MCP server |
| `windowConnection.ts` | L1 连接：端口上跑双向 `@zcode/rpc`，本进程提供 extension-host 频道并代理 Window Host 的 extension-window 频道 |
| `capabilityClient.ts` / `extensionContext.ts` | 扩展能力客户端与扩展上下文（`createExtensionContext`） |

监管要点（`src/main/extensionHostSupervisor.ts`）：崩溃预算 5 分钟内 3 次、退避 1s/2s/4s；存活探测每 5 秒一次、连续 3 次无回应判为卡死并 kill；同一时刻只给一个 Window Host 牵线，它退出后给下一个就绪者；日志环形缓冲（`EXTENSION_LOG_BUFFER_LIMIT`）由监管器独占。

## Agent 进程归属（重要）

Main 不直接 spawn Agent。Host 内的 local services（`@zcode/services`）负责真正 stdio 拉起 Agent，实现位于 `packages/services/src/zcode-agent/zcodeAgentProcessManager.ts` 与 `zcodeAgentService.ts`；desktop 侧只消费其事件与 `IZCodeAgentService` 接口。

## Renderer 加载与连接

- 本地页面：`src/main/desktopHostProcess.ts` 约 131-171 行 `loadWindow()` — 开发态（设置 `ELECTRON_RENDERER_URL`）加载 Vite dev server（端口见 `vite.config.ts`），生产 `win.loadFile(.../renderer/index.html)`（file://，query 带 restoreSession/initialWorkspacePath/launch marks）。
- Renderer 与服务连接：`src/renderer/src/main.tsx` 用 `@zcode/client` 的 `connectViaMessagePort` 消费 main postMessage 过来的 MessagePort（`InternalChannels.ServicePort`）；远程 workspace 走 `InternalChannels.ScopedServicePort`（带 attachmentId/sessionId/target），由 `src/renderer/src/remoteWorkspaceServicePortBridge.ts` 解析、`src/renderer/src/remoteWorkspaceSessionServices.ts` 构建远程 session 服务，交给 `@zcode/ui` 的 `registerRemoteWorkspaceSession`。

## 构建产物形态

`tsup.config.ts` 定义 6 个目标：main、preload（cjs）、plugin-sandbox-alias（iife）、host、scheduler、extension-host（esm）—— `@zcode/*` workspace 包被内联（noExternal），electron/node-pty/`@napi-rs/keyring`/ssh2/undici/`@larksuiteoapi/node-sdk`/yaml/node-forge/yauzl 等 external（`desktopNodeRuntimeExternals`）。renderer 用 Vite 8 多入口（root=src/renderer，`base: "./"` 适配 file://，`@` 别名指向 `../ui/src`）。

对应各目标与新增子模块的 `tsconfig.*.json` 共 9 个：`tsconfig.main.json`、`tsconfig.preload.json`、`tsconfig.host.json`、`tsconfig.scheduler.json`，以及新增的 `tsconfig.app-navigation.json`（`src/app-control-navigation`）、`tsconfig.e2e.json`（wdio E2E）、`tsconfig.extension-host.json`（`src/extension-host`）、`tsconfig.remote-main.json`（`src/main/desktopRemoteSessions.ts` 与 `webRemoteControlManager.ts`）、`tsconfig.renderer-services.json`（`src/renderer/src/remoteWorkspaceSessionServices.ts`）。

根 `pnpm typecheck` 对 desktop 检查 `packages/desktop/tsconfig.main.json`、`tsconfig.host.json`、`tsconfig.renderer-services.json`、`tsconfig.e2e.json`（`tsc -b`），外加 `tsc -p packages/desktop/tsconfig.remote-main.json --noEmit`；`tsconfig.extension-host.json` 与 `tsconfig.app-navigation.json` 经 `packages/desktop/tsconfig.json` 的 project references 间接进入。

## 风险与注意

- `src/main/index.ts`（约 2961 行）与 `src/host/index.ts`（约 4588 行）远超 800 行上限（`architecture-policy.yaml` 的 global `maxFileLines: 800` 与 `.oxlintrc.json` 的 `max-lines: 800`），属结构债务（见 [../代码不规范清单.md](../代码不规范清单.md)），改动时避免继续膨胀。
- 每窗口一个 Host 意味着多窗口 = 多个 Agent 进程与多份 local services；本地 workspace 共享该窗口 Host 的语义见仓库根 `AGENTS.md`。
- 扩展进程全 App 只有一个：扩展崩溃会触发 5 分钟窗口内的 3 次重启预算，改扩展加载路径时需同时确认监管器的退避与探测阈值。
