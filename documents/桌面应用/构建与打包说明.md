# 桌面构建与打包说明

> 范围：packages/desktop 的开发环境、运行时资产准备与 electron-builder 打包。代码基准：main@a4b44451（v4.0.0）；核对日期：2026-11-25。

## 开发环境分档

开发命令在仓库根执行，由 `scripts/dev-desktop-env.mjs` 分档（见根 `package.json` scripts）：

| 命令 | 环境 |
| --- | --- |
| `pnpm dev:desktop` | 等同 `dev:desktop:prod`（生产服务配置） |
| `pnpm dev:desktop:test` | 测试环境 |
| `pnpm dev:desktop:bytecode` | 生产 + agent 字节码模式 |
| `pnpm dev:desktop:remote-prod` | 远程生产（`scripts/dev-desktop-remote-prod.mjs`） |

包内 dev 链路（`packages/desktop/package.json`）：`pre-dev`（`scripts/ensure-local-runtime-assets.mjs` 校验本地资产 + 清空 out/）→ `dev:local-cli`（tsup --watch（当前 6 个目标，一次 watch 跑全部 config）+ vite dev + `scripts/dev.mjs` 启动 Electron；dev.mjs 等 `out/.main-build-ready` 等 marker）。

独立数据目录用 `ZCODE_DATA_BASE_DIR`（如 `ZCODE_DATA_BASE_DIR="$HOME/.zcode-dev-home" pnpm dev:desktop:test`，见根 `README.md`）。

## 运行时资产准备

`prepare:runtime-assets`（`scripts/prepare-runtime-assets.mjs`）串联：

1. 远程跨平台二进制不再在本链内准备：根 `scripts/prepare-prebuilds.mjs` 与 `.sh` 已删除，desktop 的 `prepare:remote-assets` 脚本也已删除，`ZCODE_SKIP_REMOTE_ASSETS` 全仓不再存在。Source Server 远程资源改由根 `pnpm prepare:remote-assets`（`pnpm --filter @zcode/server-cli stage:remote-assets`）单独执行，另有 `pnpm prepare:remote-assets:linux`（`stage:remote-assets --linux`）只准备 Linux 目标。
2. `prepare:agent-bundle` → `scripts/prepare-agent-node-bundle.mjs` / `stage-agent-bundle.mjs`（内置 agent JS bundle）。
3. `prepare:native-search`（原生搜索工具）、`prepare:browser-import-helper`（Windows Chrome 导入 helper）、`prepare:macos-window-bounds`（native/ 小工具）。
4. Windows 目标额外串联 `prepare:windows-runtime-host`（根 `scripts/build-windows-runtime-host.mjs`）、`prepare:windows-cua-helper`（`scripts/prepare-windows-cua-helper.mjs`，仅在装到真实 Computer Use producer 时）、`prepare:preinstalled-entry-shim`（`scripts/build-windows-preinstalled-entry-shim.mjs`）。
5. `prepare:build-meta` → `scripts/build-metadata.mjs`。

desktop 另有独立脚本 `prepare:glm`（根 `scripts/download-glm.mjs`，准备 GLM 平台二进制）；它不在 `prepare:runtime-assets` 链内——本机桌面包改为内置 agent 的 JS bundle，由 app 的 Electron Node runtime 执行。

远程功能（SSH/WSL）开发：先根 `pnpm bootstrap:with-remote`（含 mock-cdn），再 `pnpm dev:desktop`；开发态远端资源取自本地 `packages/desktop/mock-cdn` 与本地构建产物，经 SFTP 上传，不访问 CDN。

远端资源地址：`src/main/remoteCdn.ts` 解析。内置两个发布根——国内 `https://cdn.codegeex.cn/zcode/electron/releases` 与海外 `https://cdn-zcode.z.ai/zcode/electron/releases`；`locale` 以 `zh` 开头且本地时区偏移为 UTC+8 时把国内排在前面，否则海外优先（`shouldPreferDomesticRemoteCdn`）。构建期注入的 `__ZCODE_REMOTE_CDN_RELEASE_ROOTS__`（由 `CDN_DOMAIN` + `OSS_PATH_PREFIX` 生成，见 `packages/desktop/tsup.config.ts` 的 `resolveBuildRemoteCdnReleaseRoots`）存在时改用其有序列表；`ZCODE_CDN_BASE_URL` 与 `__ZCODE_CDN_BASE_URL__` 已全仓移除。`src/main/desktopRuntimeEnv.ts` 约 231-240 行开发态优先 mock-cdn。

## 生产构建与打包

- `build` = `prepare:runtime-assets` + `build:no-runtime-assets`；后者 = `prepare:build-meta` + `scripts/run-production-build.mjs`（清理并重建 out/main、out/host、out/preload、out/renderer）。
- `bundle` → `scripts/bundle.mjs`：electron-builder 打包聚合入口，含目标平台解析、asar 校验（`@electron/asar`）、原生包策略（`desktop-native-package-policy.mjs`）、运行时依赖闭包（`runtime-dependency-closure.mjs`）、NSIS patch（`patch-nsis-install-section.mjs`）。
- `electron-builder.config.js`（约 1108 行，v3.14.3 约 769 行）：appId/productName/entitlements 等，身份来自 `scripts/desktop-product-identity.mjs`。**打包目标平台未变**：mac 为 `dmg`/`zip`，win 为 `nsis`，linux 为 `AppImage`/`deb`/`rpm`/`pacman`（`.pkg.tar.zst`）。v4.0.0 在此文件新增的打包物与校验：
  - CUA Helper 打包：macOS `.app` 与 Windows runtime，仅在装到真实 Computer Use producer 时随包；`afterPack` 校验产物存在（`scripts/windows-cua-helper-assets.mjs`、`scripts/computer-use-producer.mjs`），sharp 与 koffi 运行时分别由 `scripts/sharp-package-assets.mjs`、`scripts/koffi-package-assets.mjs` 校验。
  - Windows runtime host：随包 `tools/runtime-host/zcode-runtime-host.exe` 与 `zcode-installer-process-helper.exe`，单独签名并校验；签名命令走 `scripts/powershell-command.mjs` 的 PowerShell 安全引导。
  - preinstalled entry shim：随包 `preinstalled-entry-shim/zcode-preinstalled-entry-shim.exe`，由 `scripts/build-windows-preinstalled-entry-shim.mjs` 构建（预装工具的 Windows 入口由该 shim 提供）。
  - browser-import-helper：Windows Chrome 导入 helper 改为显式 opt-in（`ZCODE_ENABLE_WINDOWS_BROWSER_IMPORT=1`），默认不打包、不签名。
  - asar 运行时依赖闭包：新增 `@babel/runtime`、`pkijs` 等闭包根注入，避免安装后启动即 `MODULE_NOT_FOUND`。
  - NSIS util patch：除 `installSection.nsh` 外新增 `include/installUtil.nsh` 的 util patch（`scripts/patch-nsis-install-section.mjs`），构建进程退出时恢复上游模板。
  - mac electron locales 校验：`afterPack` 校验打包产物的 Electron `.lproj` 语言包齐全（`scripts/mac-electron-locales.mjs`），缺失直接构建失败。
  - 平台依赖裁剪与更新发布者：`scripts/packaged-platform-dependency-prune.mjs` 裁掉不兼容平台的包；`scripts/windows-update-publisher.mjs` 从 Authenticode 签名读取并写入 Windows 更新 publisherName。
- 根入口：`pnpm bundle:desktop [-- --os mac|win|linux --arch x64|arm64]`，默认 macOS arm64，输出 `packages/desktop/dist/`（见根 `README.md` 打包章节）。
- `audit:bundle-size`：产物体积审计。
- `postinstall`：`scripts/node-pty-rebuild.mjs`。

## 相关环境变量

| 变量 | 用途 |
| --- | --- |
| `ZCODE_DATA_BASE_DIR` | 应用数据基目录（数据写入其下 `.zcode/`） |
| `CDN_DOMAIN` | 构建期远端发布根域名（逗号分隔，可配多个）；与 `OSS_PATH_PREFIX` 一起生成注入 main/host 产物的 `__ZCODE_REMOTE_CDN_RELEASE_ROOTS__` |
| `OSS_PATH_PREFIX` | 构建期远端发布根路径前缀，默认 `zcode/electron/releases`；填一个值用于全部域名，或与 `CDN_DOMAIN` 等长一一对应 |
| `ELECTRON_RENDERER_URL` | 开发态 renderer dev server 地址 |

## 交叉脚本（仓库根）

桌面相关的根级脚本：`scripts/bootstrap.mjs`（bootstrap / bootstrap:with-remote）、`scripts/build-desktop-agent-bytecode.mjs` + `compile-desktop-agent-bytecode.cjs`（agent 字节码）、`scripts/build-native-search-tools.mjs` / `package-native-search-tools.mjs`（原生搜索工具构建与打包）、`scripts/doctor-macos-release-app.sh`（macOS 发行自检）。
