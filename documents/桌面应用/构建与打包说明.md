# 桌面构建与打包说明

> 范围：packages/desktop 的开发环境、运行时资产准备与 electron-builder 打包、自动更新链路。代码基准：main@29628c9（v3.14.3）起始，自动更新一节核对至 feature/20261125-fenjue@7d9fc82d（v4.0.0，2026-11-28）。

## 开发环境分档

开发命令在仓库根执行，由 `scripts/dev-desktop-env.mjs` 分档（见根 `package.json` scripts）：

| 命令 | 环境 |
| --- | --- |
| `pnpm dev:desktop` | 等同 `dev:desktop:prod`（生产服务配置） |
| `pnpm dev:desktop:test` | 测试环境 |
| `pnpm dev:desktop:bytecode` | 生产 + agent 字节码模式 |
| `pnpm dev:desktop:remote-prod` | 远程生产（`scripts/dev-desktop-remote-prod.mjs`） |

包内 dev 链路（`packages/desktop/package.json`）：`pre-dev`（`scripts/ensure-local-runtime-assets.mjs` 校验本地资产 + 清空 out/）→ `dev:local-cli`（tsup --watch × 3 + vite dev + `scripts/dev.mjs` 启动 Electron；dev.mjs 等 `out/.main-build-ready` 等 marker）。

独立数据目录用 `ZCODE_DATA_BASE_DIR`（如 `ZCODE_DATA_BASE_DIR="$HOME/.zcode-dev-home" pnpm dev:desktop:test`，见根 `README.md`）。

## 运行时资产准备

`prepare:runtime-assets`（`scripts/prepare-runtime-assets.mjs`）串联：

1. `prepare:remote-assets` → 根 `scripts/prepare-prebuilds.mjs`（远程跨平台二进制，可用 `ZCODE_SKIP_REMOTE_ASSETS=1` 跳过；根 `pnpm prepare:remote-assets` 单独执行）。
2. `prepare:agent-bundle` → `scripts/prepare-agent-node-bundle.mjs` / `stage-agent-bundle.mjs`（内置 agent JS bundle）。
3. `prepare:native-search`（原生搜索工具）、`prepare:browser-import-helper`、`prepare:macos-window-bounds`（native/ 小工具）。
4. `prepare:build-meta` → `scripts/build-metadata.mjs`。

远程功能（SSH/WSL）开发：先根 `pnpm bootstrap:with-remote`（含 mock-cdn），再 `pnpm dev:desktop`；开发态远端资源取自本地 `packages/desktop/mock-cdn` 与本地构建产物，经 SFTP 上传，不访问 CDN。

远端资源地址：`src/main/remoteCdn.ts` 解析（默认 `https://cdn-zcode.z.ai`，可被 `ZCODE_CDN_BASE_URL` / 编译期 `__ZCODE_CDN_BASE_URL__` 覆盖）；`src/main/desktopRuntimeEnv.ts:204-212` 开发态优先 mock-cdn。

## 生产构建与打包

- `build` = `prepare:runtime-assets` + `build:no-runtime-assets`；后者 = `prepare:build-meta` + `scripts/run-production-build.mjs`（清理并重建 out/main、out/host、out/preload、out/renderer）。
- `bundle` → `scripts/bundle.mjs`：electron-builder 打包聚合入口，含目标平台解析、asar 校验（`@electron/asar`）、原生包策略（`desktop-native-package-policy.mjs`）、运行时依赖闭包（`runtime-dependency-closure.mjs`）、NSIS patch（`patch-nsis-install-section.mjs`）。
- `electron-builder.config.js`：appId/productName/entitlements 等，身份来自 `scripts/desktop-product-identity.mjs`。
- 根入口：`pnpm bundle:desktop [-- --os mac|win|linux --arch x64|arm64]`，默认 macOS arm64，输出 `packages/desktop/dist/`（见根 `README.md` 打包章节）。
- `audit:bundle-size`：产物体积审计。
- `postinstall`：`scripts/node-pty-rebuild.mjs`。

## Windows 打包耗时与提速方向（2026-11-28 实测）

ROG-9（Windows x64，Node 24.12）实测分段耗时（`[ci][timer]` 埋点读数）：

| 阶段 | 耗时 | 构成 |
| --- | --- | --- |
| `prepare:runtime-assets` | ~205s | agent bundle 全量重建 176.5s（CLI 18 子包 + 10 插件包 tsc）+ runtime-host 13.9s（MSVC）+ entry-shim 11.1s（MSVC）+ native-search 1.4s |
| `build:no-runtime-assets` | ~90s | tsup（main/host/preload/scheduler/extension-host）+ vite renderer |
| `electron-builder` | 215-439s | asar 打包 + 依赖注入 + afterPack 清理 + NSIS 压缩 |

对照 macOS：`electron-builder` 阶段 146.7s（无 NSIS、无 MSVC、无 asar 二次解包）。

已定位的耗时问题与处置：

1. **资产准备被跑两遍（已修）**：`bundle.mjs` 先跑 `prepare:runtime-assets`，随后调 `pnpm build`，而 desktop 的 `build` 脚本 = `prepare:runtime-assets + build:no-runtime-assets` → 准备阶段整体重跑一次（Windows 上约 240s）。改为只调 `build:no-runtime-assets`；副作用是 `--skip-prepare` 现在真正生效（此前会被 `build` 内含的 prepare 抵消）。
2. **Windows 专属慢点：afterPack 的 asar 二次解包**（`packaged-sourcemap-cleanup.mjs`）：为清理 `sourceMappingURL` 注释把整个 `app.asar`（约 385MB）解包再重打，解包单步实测 162s。方向：把清理前移到打包前，或在构建机排除 Defender 对构建目录的实时扫描。
3. **agent bundle 每次全量重建**：18 个 CLI 子包 + 10 个插件包逐个 `tsc`；`apps/zcode-cli/turbo.json` 已开 `cache: true`，切 turbo 构建命中缓存后可接近瞬时。
4. **同一台机器并发构建会互相踩踏**：`run-production-build.mjs` 会清理 `out/` 与 dev ready markers，`electron-builder` 会重建 `dist/`。两个构建同机并发时表现为 `app.asar` / `.extension-host-build-ready` 随机 ENOENT。约定：同一 checkout 同时只跑一个打包。

权威细节（阶段语义、跳过开关、生产产物安全收口）见仓库 `docs/electron/desktop-bundle.md`。

## 自动更新链路（2026-11-28 补）

官方正式包的增量更新是活着的线上链路，主体在 `src/main/autoUpdater.ts`（约 2200 行）+ `src/main/manifestUpdateProvider.ts`：

```txt
发现  GET /api/v1/releases/electron/manifest（自研 ManifestUpdateProvider：
      platform/channel(stable=1,preview=3)/device_mid + 登录时 Bearer JWT；
      响应是 latest.yml 同格式 YAML，files[] 为绝对 CDN URL）
下载  electron-updater blockmap 差分（useMultipleRangeRequest=false，OSS 多 Range
      Content-Type 错误会回退整包，单 Range 顺序拉仍有效；安装包/blockmap 不带 JWT）
安装  显式 quit-and-install（autoDownload / autoInstallOnAppQuit 均 false）；
      win 走 NSIS + Authenticode 双重校验（下载后 + 安装前）
```

状态机 `idle → checking → update-available → download-progress → update-downloaded`，入口分布在菜单/托盘/命令/renderer（`packages/ui/src/lib/desktopUpdateMenu.ts` 集中判定）。灰度/全量由服务端 release API `status=3/1` 控制，客户端不做灰度判断。权威文档（链路细节、安全边界、回归入口）见仓库 `docs/desktop/auto-update-*.md` 六篇。

**构建期开关**（`scripts/build-time-config.mjs`，随 define 流入 tsup/vite）：

| 变量 | 作用 |
| --- | --- |
| `ZCODE_AUTO_UPDATE` | 官方包自动更新总开关（`1`/`true`/`yes` 启用），仅 `flavor === "production"` 生效 |
| `ZCODE_FENJUE_UPDATE_MANIFEST_URL` | Fen Jue（二开版）增量更新源：完整 `latest.yml` URL。仅 `fenjue + win32` 打包态且非空时启用；为空 = fenjue 更新器整体关闭（入口点击 fail-closed）。发布流程与信任边界见 `docs/desktop/fen-jue-product-identity.md`「Fen Jue 自动更新」节 |

相关实现位置：`resolveFenJuePackagedManifestUrl()` / `shouldVerifyWindowsUpdateSignature()`（autoUpdater.ts——fenjue 未签名跳过 Windows Authenticode，由 manifest sha512 兜底）；入口 gate 为 `flavor !== "preview"`（菜单/托盘/命令/renderer 五处，Preview 永远禁用）。强更 gate（`forceUpdateGuard.ts`，index.ts 启动期调用）仍仅 production。
